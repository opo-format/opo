# OPO objects

Every IFC 4.3 element class has a generated **class template**, built on one of nine archetypes. [`archetypes.md`](archetypes.md) describes the archetypes and what every class template contains; it is the design of the templates.

Everything else about objects lives in the library repository (`opo-format/library`), as one source of truth (decision 0016):

| What | Where in the library |
|---|---|
| Class template sources: archetypes and the per-class table | `templates/archetypes/*.yaml`, `templates/classes.yaml` |
| The object catalogue and each object's specification sheet (planned objects included) | `objects/<id>/object.yaml`; `just check` writes the catalogue table `build/catalogue.md` |
| Shared rules of each object family (door and window chains, stairs, kitchens, shading, …) | `families/*.md` |
| Shared rule sets (stairs, guards, handrails, accessibility, escape windows, kitchen) with sources | `rulesets/<id>/<variant>.yaml`, `rulesets/README.md` |
| IFC coverage table | generated by `opo coverage` (`build/coverage.md`); see [`ifc-coverage.md`](ifc-coverage.md) |

Priority: **P1** reference test objects that shape the spec (spec §10) · **P2** core library for a first release · **P3** later. Markets: EU (EN and ISO norms only, decision 0009), UK and US.
